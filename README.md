# DashaEconomy — 大沙幣經濟系統

Minecraft (Paper 26.1.2 / Java 25) 的封閉式伺服器經濟。股市、拍賣行、伺服器商店與礦物收購
四個系統合成一個插件，共用同一套 **大沙幣** 帳本。

由 [stock_plugin](https://github.com/SQL1024-sql/stock_plugin) 與
[ah_plugin](https://github.com/SQL1024-sql/ah_plugin) 整併而來。

---

## 為什麼是一個插件而不是三個

三個系統要共用同一個餘額。做成一個插件才能讓「買股票」和「買拍賣行的東西」爭用**同一把鎖**——
玩家沒辦法開兩個視窗把同一筆大沙幣花兩次。手續費也才能落進同一本帳，`/eco stats`
講的總量才是事實而不是猜測。

---

## 貨幣流通模型

整個經濟是封閉的。大沙幣只有兩個地方會憑空出現，其餘都是轉移或銷毀。

| 管道 | 方向 | 性質 |
|---|---|---|
| `/sell` 賣礦物 | 產出 | **唯一主要 faucet**，有動態降價 + 每日額度 |
| 股票賺賠 | 雙向 | 對手是伺服器，玩家淨賺 = 系統印鈔 |
| 拍賣行成交 | 零和 | 玩家 ↔ 玩家 |
| 股票手續費 | 銷毀 | sink |
| 上架費 + 成交抽成 | 銷毀 | **持續性 sink** |
| `/store` 買建材 | 銷毀 | sink |

沒有簽到、沒有殺怪掉錢、沒有任務獎勵、沒有 `/pay`。

**大沙幣是帳戶餘額，不是背包物品。** 這是刻意的：物品會被複製（複製物品＝複製鈔票），
拍賣行要能在賣家離線時收款，手續費要能真的銷毀，`/eco stats` 要能算出散落各地的總量。

---

## 七道防線

### 1. 礦物收購：動態降價 + 每日額度

每賣出一個，該礦物的全服「供給池」+1，價格隨之下滑；供給池以 24 小時半衰期自己衰減。
全服狂挖鑽石 → 鑽石價自己掉 → 產出自動剎車，不用手動追著改 config。

價格用**積分**計算而非 `數量 × 現價`，所以整疊賣掉和一個一個賣，拿到的錢完全一樣。

每人每日 8000 大沙幣的收購上限，是防「掛機農場 + 分身帳號」的硬天花板。

### 2. 礦物分級：按「能不能掛機量產」而不是稀有度

程式**無法分辨**一塊鐵錠是玩家挖來的還是鐵傀儡農場刷出來的。所以只能用定價處理：

- **A 級**（鑽石、遠古遺骸、青金石、石英）— 只能挖，沒有農場 → 正常價
- **B 級**（紫水晶、銅、紅石、煤）— 有農場但要成本 → 低價
- **C 級**（鐵、金、綠寶石）— 掛機無限產 → **預設不收購**

### 3. 股市：跟真實市場連動

**69 檔真實股票**，價格直接抓真實行情，**不需要申請任何 API 金鑰**。

| 市場 | 檔數 | 例子 |
|---|---|---|
| 美股 | 40 | 蘋果、輝達、微軟、特斯拉、Meta、波克夏、可口可樂 |
| 台股 | 14 | 台積電、鴻海、聯發科、台達電、中華電、0050 |
| 日韓港 | 9 | 豐田、索尼、軟銀、三星、SK海力士、騰訊、阿里巴巴 |
| 加密貨幣 | 2 | 比特幣、以太幣 |
| 指數 | 4 | 標普500、那斯達克、台灣加權、日經225 |

外幣會依 `currency-rates` 換算成大沙幣，所以三星（韓元）和耐吉（美元）擺在一起可以直接比。

**漲幅也跟著現實走。** 遊戲內顯示的「今日」漲跌，是用該交易所自己的前一日收盤當基準算的 ——
跟玩家手機上看到的數字是同一個。實測 13 檔對照 Yahoo，12 檔完全一致到小數點後兩位
（比特幣差 0.08pp，因為它 24 小時交易，兩次抓價之間真的動了）。

**三種價格來源**（`stocks.yml` 的 `price-source`）：

- `real` — 純真實行情。**新聞整組停用**（見下方）
- `simulated` — 原本的隨機漫步 + 新聞驅動，完全不連外
- `hybrid` — 真實價格當基準，新聞在上面疊一層會衰減的溢價。現實與機制兩者都保留

> ⚠ **選 `real` 之前要知道的事**
>
> 真實價格代表玩家可以用手機看到未來。他先看到輝達即時漲 5%、而插件下一次更新還沒到，
> 那就是穩賺 —— 這比原本的新聞機制危險得多。
>
> 緩解：把 `update-interval-seconds` 調短、保留手續費與持股上限、或改用 `hybrid`
> 讓價格沒那麼容易預測。

抓價全程在背景執行緒，不會卡主線程。抓不到的代號**沿用上一次的價格**（絕不歸零 ——
歸零等於讓玩家免費買下一間真實公司），並在管理面板列出是哪幾檔。
休市時價格凍結，GUI 會標示「● 休市」而不是讓玩家以為壞了。

### 4. 股市：對手是無限資金的做市商

玩家低買高賣賺到的錢不是從別的玩家口袋來的，是憑空產生的。五道限制：

| 機制 | 預設 |
|---|---|
| 買/賣手續費 | 各 1%，直接銷毀 |
| 大單滑價 | 買越多越貴、賣越多越便宜 |
| 單筆 / 持股上限 | 200 股 / 1000 股 |
| 單日漲跌幅 | ±20%（台北時間午夜重置） |
| **新聞停牌** | 60 秒 |

**停牌是最關鍵的一道。** 發布流程是：廣播「即將發布重大消息」→ 該股停牌、股價已開始移動 →
停牌結束、公佈標題、恢復交易。沒有它，看到利多全押就是保證獲利，股市直接變提款機。

### 5. 新聞：只在價格是模擬的時候存在

新聞推不動蘋果的真實報價。所以 `price-source: real` 時，整套新聞機制會**自動停用**：

| | `real` | `hybrid` / `simulated` |
|---|---|---|
| 自動發布新聞 | ❌ 不發 | ✅ |
| 停牌 | ❌ 不停 | ✅ |
| 內線鎖 | ❌ 不鎖 | ✅ |
| 手動發布 | ⚠️ 可以，但只是廣播文字 |  ✅ 真的會推動股價 |

這是刻意的。停牌是為了防止玩家搶在價格變動前下單 —— 價格既然不是我們決定的，
就沒有東西好搶，留著只會無故鎖住某檔股票 60 秒，玩家還看不出原因。

管理面板和發布畫面在這個模式下都會直接標示「不會影響股價」，指令回覆也一樣，
不會讓管理員以為自己發了一則有效力的消息。

**想讓新聞真的有用，就把 `price-source` 改成 `hybrid`** —— 真實價格當基準，
新聞在上面疊一層會衰減的溢價，兩邊都保住。

### 6. 防內線交易

管理員用 `/stock news` 發布後，自己 10 分鐘內不能交易那檔股票。
所有人工發布都寫進稽核紀錄，用 `/stock audit` 查。

### 7. 反向通道守門員

商店賣的方塊如果能拆成收購清單裡的礦物，就是無限印鈔機：
買方塊 → 拆成礦物 → 賣回系統 → 賺差價 → 重複。

啟動時會走 **Minecraft 真實的合成表**自動檢查（不是寫死的清單，所以新版本加方塊、
你改 config 都還能用），違規會在 console 印警告並附建議價。隨時可用 `/eco audit` 手動查。

規則：**商店價 ≥ 拆解後的礦物收購總值 × 1.5**

## 統一入口：`/eco` 總管 GUI

輸入 `/eco`（或 `/money`）開啟總管，**所有功能都從這一頁進去**，不用記五個指令：

```
              ┌─ 你的頭像：餘額 / 持股市值 / 總資產 / 今日額度 / 上架數
              │
  賺錢 ──┬─ 📈 股市          ─→ 看盤、買賣、走勢圖
         ├─ 📦 拍賣行        ─→ 瀏覽、上架、購買
         └─ ⛏️ 賣礦物        ─→ 收購站（即時價、額度條、一鍵全賣）

  花錢 ──── 🏪 伺服器商店    ─→ 分類 → 商品頁

  其他 ──┬─ 💼 我的持股      ├─ 📥 取貨箱
         ├─ 📋 我的上架      ├─ 📰 財經新聞
         └─ 🏆 富豪榜        └─ 📖 這套經濟怎麼運作

  管理 ──── ⚙️ 管理面板（僅 dasha.admin 可見）
              ├─ 經濟報告（左鍵 7 天 / 右鍵 30 天）
              ├─ 反向通道檢查
              ├─ 股市淨資金流即時顯示
              ├─ 自動新聞開關（寫回 stocks.yml，重開仍有效）
              ├─ 發布新聞 → 選股票 → 選方向/強度/標題 → 發布
              ├─ 新聞稽核紀錄
              ├─ 手動改股價 / 手動更新股價
              ├─ 玩家錢包管理 → 發放 / 扣除 / 設定 / 查持股
              └─ 重新載入設定
```

每個子選單左下角都有 **返回主選單**（🌟 下界之星）。需要自由輸入的地方
（價格、金額、玩家名、新聞標題）會關閉介面請你在聊天欄輸入，打「取消」放棄，
輸入完自動回到原本的位置。

指令仍然全部保留 —— 總管只是多一條路，不是取代。

## 要盯的數字

`/eco stats` 裡的 **股市淨資金流**。挖礦是設計上的 faucet 而且有上限；股市只有在玩家
整體贏過做市商時才是 faucet，而除了那五道防線之外沒有東西擋得住它。

**如果股市淨資金流持續為正而且超過挖礦收入，就是股市在印鈔** —— 調高手續費或收緊持股上限。

## 疑難排解

### 「連 OP 都不能用 /eco」

**幾乎一定是指令撞名，不是權限問題。**

`/eco`、`/money`、`/bal`、`/balance`、`/sell`、`/shop`、`/market` 這些都是 **EssentialsX**
（以及不少商店插件）也會註冊的名字。同一個名字只有一個插件搶得到，輸的那個會被
Bukkit 靜靜地丟到 `plugin:command` 形式，於是指令打下去有反應、卻是別人的插件在回話 ——
看起來就跟沒權限一模一樣，而且 OP 也救不了，因為根本沒走到權限檢查。

插件啟動時會自動偵測並在 console 印出來，例如：

```
⚠ 有指令名稱被其他插件搶走了：
  • /eco 被 EssentialsX 佔用，請改打 /dasha
  • /sell 被 EssentialsX 佔用，請改打 /sellore
連 OP 也一樣 —— 那不是權限問題，是名字撞到了。
```

三種解法：

1. **直接用還活著的別名** —— `/dasha`、`/sellore`。最省事
2. **用完整名稱** —— `/dashaeconomy:eco`，一定有效
3. **搶回名字** —— 改本插件 `plugin.yml` 的 `aliases`，或用伺服器的 `commands.yml` 重新指派

### 真的是權限問題的話

| 節點 | 預設 | 沒有它會怎樣 |
|---|---|---|
| `dasha.admin` | OP | 管理面板不出現，管理指令全部拒絕 |
| `dasha.stock` / `dasha.market` / `dasha.store` / `dasha.sell` | 全開 | 對應的總管按鈕點下去說沒權限 |

用 LuckPerms 的話注意：如果你把 `dasha.*` 設成 `false`，那會**蓋過** OP 身分。

## 已知的取捨

- **鐵/金/綠寶石預設不收購。** 一台鐵傀儡農場掛一晚的產量超過認真挖礦玩家一整個月，
  而系統無法分辨。要開放請把 `sell.yml` 裡的註解拿掉，但務必壓低價格並保留每日額度。
- **指令別名可能撞插件。** `/shop`、`/market`、`/sell` 這些常見別名如果和其他插件衝突，
  改 `plugin.yml` 的 `aliases`。
- **餘額寫入是非同步的。** 記憶體是真相來源，資料庫是耐久鏡像，由單一寫入執行緒依序落盤。
  伺服器硬當可能丟掉最後幾秒的變動。
